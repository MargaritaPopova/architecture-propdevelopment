## Cписок требований к интеграции:

Приложение будет передавать чувствительные данные (биометрию и номера автомобилей), поэтому требования к интеграции высокие.

1. Зашифрованное соединение для общения с API (https/vpn)
2. Зашифрованный канал для передачи перс. данных (TLS)
3. Биометрические данные должны не храниться на стороне PropDevelopment, а только на стороне сертифицированного партнера
4. Доступ к данным строго по ролям
5. Все главные действия (запросы на открытие, распознавание, ошибки, попытки входа) должны журналироваться
6. Интеграция должна поддерживать отправку логов событий в централизованную SIEM-систему PropDevelopment 
7. Использовать OAuth 2.0/ OpenID Connect для общения с партнером
8. Использовать RBAC или ABAC для доступа к командам (открыть шлагбаум, открыть дверь)

Пояснение к п.3: Согласно ФЗ-152, биометрия — это чувствительные персональные данные, которые требуют специального правового основания,
прямого согласия субъекта на их использование (в явной форме), строгого режима хранения, обработки и защиты. Если PropDevelopment сам будет хранить биометрию, 
то придется оформлять юридическую модель хранения таких данных, внедрять системы хранения, шифрования, контроля доступа, журналирования, проходить дополнительные аудиты.
А так как функционал предоставляет партнер, по договору, эти обязательства можно возложить на него. Разумеется, необходимо провести внутренний аудит партнера, 
а может ли он предоставить нужные механизмы защиты персональных данных.
